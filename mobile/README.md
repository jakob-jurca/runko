# Runko mobile (Expo)

iOS and Android app. It imports the shared engine from `../src/core` unchanged
(plan engine, coach, strings, subscription rules). Only two files differ per
platform: `platform/env.js` (replaces `src/core/env.js`) and
`platform/knowledge-files.js` (generated by `npm run gen:knowledge`, replaces
`src/core/knowledge-files.js`). Metro swaps them in, see `metro.config.js`.
All text is Slovenian, from `src/core/strings.js`.

## Setup (once)

```
cd mobile
npm install
copy .env.example .env      # fill in the two values, same as VITE_SUPABASE_* in ../.env
```

`.env` holds only `EXPO_PUBLIC_SUPABASE_URL` and `EXPO_PUBLIC_SUPABASE_ANON_KEY`.
There is no AI key in the app; the coach calls the `ai-proxy` Edge Function.

## Run on your phone with Expo Go (Windows)

1. Install **Expo Go** from the App Store / Google Play. Phone and PC must be on the same Wi-Fi.
2. `cd mobile` then `npm start`.
3. Scan the QR code: Android with the Expo Go app, iPhone with the Camera app.
4. If the phone cannot reach the PC (firewall, guest Wi-Fi), run `npx expo start --tunnel` instead.
5. Allow Node.js through Windows Firewall for private networks if asked.

Limits of Expo Go: no push, and the `runko://` link only works in a real build. For the password
reset link use the `exp://` URL that Expo Go prints (see Supabase redirect list in `PROGRESS.md`
and the Auth section below). Notifications scheduled locally do work in Expo Go on iOS; on Android
Expo Go has restricted notification support, use a development build (`eas build --profile development`).

## Preview in a browser

`npm run web` opens the app at http://localhost:8081. Layout and data work; notifications, haptics and
the secure-store session are native only (the browser uses AsyncStorage).
